# Contributing

This document is the contract for adding or changing a tool. Read it once; the checks in `npm run lint` and `npm test` enforce most of it.

## Layout you will touch

| Path | Purpose |
|---|---|
| `server/src/tools/<group>.ts` | Tool definitions: name, description, zod input, optional Node handler |
| `server/src/schemas/common.ts` | Shared schemas: CompRef, LayerRef, PropertyPath, Easing, Color, Vec2, Vec3, TimeArgs, KeyframeSpec, Spatial, enums |
| `server/src/scripts/commands/<group>.jsx` | ExtendScript implementation, one `MCP.register(...)` per tool |
| `server/src/scripts/lib/*.jsx` | Shared ExtendScript: core helpers, resolvers, serializers, easing, colour, undo |
| `server/test/bridge-mock/responses/<group>.js` | Mock result shapes for the commands in that group |
| `server/test/bridge/<group>.test.ts` | Tests that call the tools through the MCP server and the mock bridge |
| `docs/TOOLS.md` | Generated by `npm run gen-docs`. Never hand-edit. |

## Adding a tool: the checklist

1. Schema. Add the input shape to the tool in `server/src/tools/<group>.ts`, reusing `CompRef`, `LayerRef`, `PropertyPath`, `Easing`, `Color`, `TimeArgs` and the enums from `schemas/common.ts`. Every field gets `.describe()` with units and defaults. No `any`.
2. Tool definition. Call `defineTool(server, { name, group, description, input, mutating?, timeout?, bridge?, toBridgeArgs?, handler? })`.
   - `name` is kebab-case. The bridge command is the name in camelCase unless `bridge` is set. `bridge: null` means Node-only and needs `handler`.
   - `mutating: false` for read-only tools (it sets the MCP `readOnlyHint` annotation).
   - `timeout: 'render'` for anything that can take longer than a few seconds.
   - The description follows the template below, 60 to 200 words.
3. Bridge command. In `server/src/scripts/commands/<group>.jsx` add `MCP.register("commandName", function (args, ctx) { ... }, { mutating: true|false })`. ES3 only. Use the shared resolvers. Return the changed state (see "Return shapes").
4. Nothing else to register. The panel dispatches from `MCP.commands`, the server derives the command name from the tool name, and a unit test checks that every bridge-backed tool has a registered command.
5. Mock response. Add `commandName: (args) => ({ ...plausible shape... })` to `server/test/bridge-mock/responses/<group>.js`. Unknown commands still round-trip with a generic echo, but the tests for your tool should assert the real shape.
6. Test. Add cases to `server/test/bridge/<group>.test.ts` using `makeTestBridge`, `makeTestServer` and `callTool` from `test/helpers.ts`: valid call returns the shape, invalid input is rejected before anything is sent, and any Node-side logic (transforms, gating) behaves.
7. Run `npm run build && npm run lint && npm test && npm run gen-docs` from the repository root.

## Description template

```
<One sentence: what it does.>

Use when: <situation>. Do not use for: <adjacent situation> (use <other-tool> instead).

Inputs: <the non-obvious ones, with units and defaults>.
Returns: <what comes back, so the agent knows what it can verify>.
Notes: <undo behaviour, idempotency, version limits, common mistakes>.
Example: <one realistic call in prose>.
```

Written as one string with the labels `Use when:`, `Do not use for:`, `Inputs:`, `Returns:`, `Notes:`, `Example:` in that order. Plain sentences. No em dashes. No marketing words.

## ExtendScript rules (ES3)

After Effects runs ExtendScript, which is ECMAScript 3. `npm run lint` parses every `.jsx` with acorn at `ecmaVersion: 3` and fails on anything newer.

Do not use: `let`, `const`, arrow functions, template literals, default parameters, destructuring, spread, getters and setters, trailing commas in object or array literals, reserved words as property names without quotes (`obj.default` must be `obj["default"]`), `Object.create`, `Object.assign`, `Array.from`, `Array.prototype.includes`, `String.prototype.startsWith`, `JSON` without the shim.

Available through `lib/polyfills.jsx` and `lib/json.jsx`: `Array.prototype.indexOf`, `lastIndexOf`, `forEach`, `map`, `filter`, `some`, `every`, `reduce`, `Array.isArray`, `Object.keys`, `String.prototype.trim`, `Function.prototype.bind`, `Date.prototype.toISOString`, `Date.now`, `JSON.parse`, `JSON.stringify`.

Other rules:

- `var` everything. Declare variables at the top of the function when the same name is reused in loops.
- Function declarations only at the top level of a file or directly inside a function body, never inside `if` or `try` blocks.
- Wrap property reads that may throw on some layer types in `try/catch` or `_mcpTry(function () { ... }, fallback)`.
- Never call `alert()` or open dialogs.
- `Layer.moveBefore()` does not exist. Use `moveAfter`, `moveToBeginning`, `moveToEnd`, or the two-step trick in `MCP.placeNewLayer`.
- Never `app.beginUndoGroup` inside a command. The panel opens one group named `MCP: <command>` around every command; `batch` runs its steps inside one group.

## Shared ExtendScript API

Everything lives on the `MCP` object (see `lib/core.jsx`, `lib/resolve.jsx`, `lib/serialize.jsx`, `lib/easing.jsx`, `lib/color.jsx`).

Errors and arguments:

- `MCP.fail(message, code, details)` throws. Codes in use: `not-found`, `invalid-argument`, `ambiguous`, `unsupported`, `script-error`, `io`. The message should tell the agent what to do next and list alternatives.
- `MCP.requireArg(args, "name")`, `MCP.arg(args, "name", fallback)`, `MCP.num(v, fallback)`, `MCP.bool(v, fallback)`, `MCP.isDefined(v)`, `MCP.isArray(v)`.
- `MCP.requireVersion(24, "Font API")` throws `unsupported` on older versions.
- `MCP.invoke("commandName", args, ctx)` calls another registered command without a new undo group.

Time:

- `MCP.timeArg(comp, args, defaultTime)` reads `args.frame` (wins) or `args.time` in seconds.
- `MCP.durationArg(comp, args, "duration", "durationFrames", fallback)`.
- `MCP.frameOf(comp, seconds)`, `MCP.snapToFrame(comp, seconds)`, `MCP.frameDuration(comp)`.

Resolvers:

- `MCP.resolveComp(args.comp)`: `{id}`, `{name}`, `{active:true}`, or nothing for the active composition.
- `MCP.resolveLayer(comp, args.layer)`: `{index}`, `{id}`, `{name}`. Ambiguous names error with the matches.
- `MCP.resolveCompAndLayer(args)` returns `{comp, layer}`.
- `MCP.resolveLayers(comp, spec)`: array of refs, `{selected:true}`, `{all:true}`, `{indices:[...]}`, `{names:[...]}`.
- `MCP.resolveProperty(layer, path)`: display-name or matchName path, string with `/` or array. Errors list the children of the deepest group that resolved. `MCP.resolvePropertyOptional` returns null instead.
- `MCP.resolveEffect(layer, ref)`: name, matchName, index, or an object with one of those.
- `MCP.resolveItem(ref, "comp"|"footage"|"folder")` for project items.
- `MCP.findProp(root, name)` depth-first by display name or matchName. `MCP.childProp(group, token)` direct child. `MCP.childNames(group)` for error messages. `MCP.pathOf(prop)` gives `{path, matchPath}`.

Serializers (return these, do not invent new shapes):

- `MCP.serialize.comp(comp)`, `MCP.serialize.compRef(comp)`
- `MCP.serialize.layer(layer, {keyframes:true})`, `MCP.serialize.layerRef(layer)`
- `MCP.serialize.property(prop, {children:true, depth:2, values:true, keyframes:true})`
- `MCP.serialize.keyframe(prop, index)`, `MCP.serialize.effect(fx, {properties:true, depth:1})`, `MCP.serialize.item(item)`, `MCP.serialize.marker(markerValue)`, `MCP.serialize.textDocument(doc)`
- `MCP.serialize.propertyResult(layer, prop, extra)` is the standard result of a property mutation.
- `MCP.serialize.rawValue(v)` turns TextDocument, Shape, MarkerValue and arrays into JSON.

Enums: `MCP.enums.blendModeValue(name)`, `blendModeName(value)`, `labelIndex(nameOrIndex)`, `trackMatteValue(name)`, `trackMatteName(value)`, `interpolationValue(name)`, `interpolationName(value)`, `MCP.justificationValue(name)`.

Easing and keyframes:

- `MCP.easing.setKey(prop, time, value, spatialMode)` sets a value at a time and returns the key index; it zeroes spatial tangents unless `spatialMode === "auto"`.
- `MCP.easing.applySegment(prop, keyIndex, easingSpec)` applies easing to the segment arriving at that key.
- `MCP.easing.applyToKeys(prop, [indices], spec)`, `MCP.easing.keyIndexAtTime(prop, t, tolerance)`, `MCP.easing.overshootKey(t0, v0, t1, v1)`.
- `MCP.coerceValue(prop, raw)` and `MCP.valueForProperty(prop, raw)` turn JSON strings and text into the value type the property wants.

Colour: `MCP.color.rgba(value, fallback)` returns `[r,g,b,a]` in 0 to 1 from hex, arrays (0 to 1 or 0 to 255) or objects. `MCP.color.rgb(value)` drops alpha. `MCP.color.toHex(arr)`.

Effects: `MCP.fx.add(layer, identifier)`, `MCP.fx.addFirstAvailable(layer, [matchNames])`, `MCP.fx.existing(layer, identifier)`, `MCP.fx.setBy(effect, "Property Name", value, notes)`, `MCP.fx.applySettings(effect, settingsObject)`, `MCP.effectsGroup(layer)`.

Layers: `MCP.placeNewLayer(comp, layer, args)` applies name, position, timing, label, parent, blendMode, threeD, above, below, toBottom. `MCP.applyLayerTiming(comp, layer, args)`. `MCP.textDocProp(layer)`, `MCP.applyTextStyle(doc, args)`. `MCP.shape.addShapeGroup(container, args, comp)`.

## Return shapes

Every mutating command returns what it changed, not `{success: true}`:

- Layer creation and changes: `{ composition: compRef, layer: MCP.serialize.layer(layer) }` plus any extra fields.
- Property changes: `MCP.serialize.propertyResult(layer, prop, { keyframe, keyIndex, ... })`.
- Bulk operations: `{ count, failed, results: [{ status: "ok"|"error", ... }] }`.
- Read-only commands return plain summaries built from the serializers.

Round numbers with `MCP.round(n)` or `MCP.roundValue(v)` (4 decimals) so results stay readable.

## Node-side conventions

- `strict: true`, no `any`. Use `z.unknown()` for values whose type depends on the property.
- A tool that needs Node work before or after the bridge uses `handler: async (args, ctx) => { ... ctx.run(command, args) ... }`. Return a plain object (wrapped as JSON text) or a full `CallToolResult` (for images).
- `toBridgeArgs` reshapes validated args before they are sent; `batch` uses it too.
- Long operations: `timeout: 'render'` (default 10 minutes, `AE_MCP_RENDER_TIMEOUT_MS`).

## Running the mock bridge and the real thing

- `npm test` runs everything against the mock bridge in a temporary folder. No After Effects needed.
- `npm run mock-bridge` runs the mock against the real bridge folder so you can drive the server from an MCP client without After Effects.
- `npm run smoke` runs a short checklist against a real After Effects with the panel open.
- After changing any `.jsx`: `npm run build && npm run install-bridge`, then close and reopen the panel in After Effects.

## Writing style

Plain, direct sentences. No em dashes anywhere in any file. No words like "seamless", "leverage", "cutting-edge", "robust" or "powerful". Say what the thing does.
