# Decisions

One line per judgement call, newest at the bottom. Phase numbers refer to `docs/PLAN.md`.

- P0: The audit and plan were written against the repository as committed on 2026-09-14 (commit b0e7731). No code was changed in Phase 0.
- P0: Development and builds were done in a local clone outside the OneDrive folder that holds the original files, because `node_modules` in a OneDrive path failed to populate and file reads timed out. The OneDrive copy is synced from GitHub after each push.
- P0: The bridge command name for every tool is the tool name converted from kebab-case to camelCase. No hand-maintained mapping table exists; a test asserts every tool that goes through the bridge has a matching registered command.
- P0: `convert-to-hold`, `convert-to-linear` and `convert-to-bezier` were merged into one `set-keyframe-interpolation` tool with a `type` argument, to keep the one-tool-one-command rule. Same for `enable-expression` and `disable-expression`, merged into `set-expression-enabled`.
- P0: `get-layer-clip-frames` is not kept as a tool. Its frame arithmetic is returned by `get-layer-details` and by every tool that changes timing.
- P0: The panel `.jsx` files contain no em dashes and are moved byte-identical. The four `GUIDE.md` files do contain em dashes and are edited in Phase 6 as the task allows.
- P1: The compiled entry point moves from `ae-mcp-setup/after-effects-mcp/build/index.js` to `server/build/index.js`. It is still `build/index.js` relative to the server package, but anyone with an existing `claude mcp add` entry must re-run setup or point it at the new path.
- P1: Root `package.json` uses npm workspaces with `server` as the only workspace, so one `npm install` at the root installs everything and CI can run `npm ci` once. The server's own `package-lock.json` was removed in favour of the root lock file.
- P1: The bridge assembler concatenates `lib/` in a fixed order (polyfills, json, core, color, undo, resolve, serialize, easing, then any others alphabetically), then `commands/**` sorted by path, then the panel. Every included file is marked with a `/* ---- path ---- */` banner so runtime error line numbers can be traced back.
- P1: The split of the old bridge into files kept every function unchanged except two lint fixes: a trailing comma in the `curves` template object and an em dash in a comment. Behaviour is identical.
- P1: The ten dead standalone scripts were moved to `legacy/standalone-scripts/` rather than deleted, with a README explaining they are not built.
- P1: Byte order marks were stripped from every moved source file.
- P1: The panel `.jsx` and `GUIDE.md` files were moved byte-identical. Panel folder names use kebab-case; the `.jsx` file names keep their spaces because After Effects shows the file name in the Window menu and the guides refer to it.
- P2: Commands are one file each under `queue/`, named `cmd-<ms>-<seq>-<id>.json`, written to a temp name and renamed so the panel never reads a partial file. The panel renames a file to `running-` before executing it, so a crash cannot re-run a mutating command; leftover `running-` files are turned into "interrupted" error results when the panel starts.
- P2: Result files are kept in `results/` so `get-results` can fetch them by id, and removed by the server on start when older than `AE_MCP_RESULT_MAX_AGE_MS` (default one hour).
- P2: On timeout, if the command file is still pending the server deletes it and reports `bridge-not-running`, so a command never runs minutes later when the panel opens. If the panel already picked it up, the server reports `timeout` with the id and leaves it running.
- P2: Easing describes the segment that arrives at a keyframe: it sets the out handle of the previous key and the in handle of the key. Presets use CSS-style naming (ease-out is slow at the end, the right default for entrances). Cubic-bezier is approximated per segment as influence = x1 * 100 and (1 - x2) * 100 with speeds from the handle slopes and the segment's value delta; values of y outside 0 to 1 are not representable.
- P2: Spatial keyframes (Position, Anchor Point) get zero spatial tangents by default so motion paths are straight lines; `spatial: "auto"` keeps After Effects auto-bezier.
- P2: Colours are normalised on the Node side by a zod transform, so every bridge command receives `[r, g, b, a]` in 0 to 1. The bridge also has `MCP.color.rgba` as a safety net and for the rig commands.
- P2: `@style.*` references are resolved on the Node side before validation, so the panel never sees them.
- P2: The effect template names exist in both `server/src/tools/effects.ts` (as the enum the model sees) and `commands/effects.jsx` (the implementation). A unit test fails if the two lists differ.
- P2: Drop Shadow opacity is written as `percent * 2.55` because the effect stores 0 to 255 when set by script, as found while building the Edge Glow panel. Unverified on other versions.
- P2: `run-extendscript` exists but is refused unless `AE_MCP_ALLOW_RAW_SCRIPT=1`; the tool description says so.
- P2: Tools are registered with `registerTool` (the SDK deprecated `server.tool`) with `readOnlyHint` and `destructiveHint` annotations derived from the `mutating` flag.
- P2: The panel handles up to 20 queued commands per tick and stops after 4 seconds so the After Effects UI stays responsive; it writes `heartbeat.json` at most every 2 seconds.
- P2: The panel uses the `thisObj instanceof Panel` pattern from the builder panels so it docks like a normal ScriptUI panel.
- P2: The old `run-script`, `test-animation`, `run-bridge-test`, `add-any-effect`, `mcp_aftereffects_*` and `get-layer-clip-frames` tools are gone as planned in `docs/PLAN.md`. The `_responseTimestamp` and `_commandExecuted` fields no longer exist; results carry `id`, `command`, `status`, timing and versions.
- P2: Effect matchNames used by the templates (for example `ADBE VR Chromatic Aberrations`, `CC Vignette`, `frameFX/enabled` for the outline layer style) could not be verified against a running After Effects during this work. Each template fails with an "unsupported" error naming the effect if it cannot be added.
- P3: The tool groups were implemented in parallel by separate workers, each owning one set of files (tool file, command file, mock responses, tests), against the contract in `docs/CONTRIBUTING.md`. Their judgement calls follow.
- P3 render: The Node side passes `outputDir` (its frames folder) to `seeFrame` and `seeFrames`; the panel uses it when present and falls back to its own frames folder, so both sides agree even when `batch` sends the command without it.
- P3 render: `see-frame`, `see-frames`, `export-frame-png` and `export-still-sequence` are marked read-only even though `see-frame` moves the playhead by default; they do not change project content.
- P3 render: Requested times are snapped to a frame and clamped to the composition range rather than failing on out-of-range input.
- P3 render: `see-frames` accepts `frames[]` over `times[]` over `count` (evenly spaced, both ends included), capped at 25 frames; `export-still-sequence` caps at 300 unless `allowLarge`.
- P3 render: The contact sheet marks each tile with a one pixel border and returns the tile-to-time map as text instead of drawing digits (no font rasteriser); tiles have a 2 px gap on dark grey and `maxWidth` shrinks them proportionally.
- P3 render: The render-queue fallback for `saveFrameToPng` (After Effects before 22.3) temporarily unqueues other items, renders one PNG with a `_[#####]` pattern and renames it; unverified on a real After Effects.
- P3 render: `render` with `itemIndices` unqueues every other item for that run and does not restore them; `clear-render-queue` refuses while rendering.
- P3 render: aerender lookup order is `aerenderPath`, then `AE_MCP_AERENDER_PATH`, then the newest install folder; aerender runs detached with its log under the bridge folder and there is no polling tool for it.
- P3 render: Export paths and output directories expand `~` on the Node side.
- P3 project: `new-project` and `reduce-project` require `confirm: true`, checked on the Node side before any bridge traffic and again in ExtendScript, so `batch` is protected too.
- P3 project: `new-project` and `open-project` take `discardChanges`; a dirty project without it fails instead of letting After Effects open a save dialog that would block the bridge. When the dirty flag cannot be read (old versions) the project is treated as dirty.
- P3 project: `save-project` accepts an optional `path` for untitled projects; `save-project-as` refuses to overwrite unless `overwrite: true` and appends `.aep` when missing.
- P3 project: `delete-item` needs `force` when the item is used in comps, is a comp with layers, or is a folder with contents.
- P3 project: `import-file` imports `.aep` files as a project folder automatically; `importAs` values the file type cannot support fail with `unsupported` instead of being ignored.
- P3 project: `collect-files` has no scripting API; `dryRun: true` lists every referenced footage file and missing files; any other call fails with `unsupported`.
- P3 composition: `precompose` with `trimToLayers` trims the new layer and shortens the precomp without moving the layers to time zero, so absolute-time expressions keep working; `moveAllAttributes: false` with more than one layer fails early (an After Effects restriction).
- P3 composition: `set-composition-settings` applies fields in a fixed order (name, size, pixel aspect, frame rate, duration, colour, motion blur, resolution, display start, flags) so frame-based values use the new frame rate.
- P3 composition: `crop-composition-to-region` skips parented layers, cameras and lights and reports them, offsets Position values or keyframes, handles separated dimensions, and flags layers whose Position has an expression. `fromLayer` bounds ignore rotation.
- P3 composition: `set-work-area` and `set-current-time` snap to frames and clamp to the composition; the work area must be at least one frame.
- P3 keyframes: One shared key selection schema (`"all"`, indices, or a time range inclusive with half a frame of tolerance) is used by every keyframe tool that acts on several keys.
- P3 keyframes: `clear-keyframes` keeps the pre-expression value (`valueAtTime(t, true)`), not the expression output.
- P3 keyframes: `move-keyframes` and `reverse-keyframes` read, remove and rewrite keys; a moved key that lands on an unselected key overwrites it and reports it. Reverse swaps in and out ease, negates spatial tangents and keeps holds on their original segments.
- P3 keyframes: `copy-keyframes` checks value shape compatibility (array length, number, or text, shape and marker types) and measures `frameOffset` in the target composition's frame rate; with `toComp` and no `toLayer` the same-named layer is used.
- P3 keyframes: `bake-expression-to-keyframes` replaces existing keys, temporarily enables a disabled expression while sampling, and writes linear keys with zero spatial tangents; large ranges over 5000 samples need `allowLarge`.
- P3 keyframes: `stagger-keyframes-across-layers` uses a seeded Park-Miller generator for `random` order so runs repeat.
- P3 expressions: Preset code is generated for the property's dimensionality at build time rather than branching inside the expression; `elastic` scales by the size of the last move rather than velocity so it differs from `inertia-bounce`.
- P3 expressions: `add-expression-control` always adds a new control (no idempotency) because several sliders with different names on one layer is the normal case; dropdown items use `setPropertyParameters` in a try with a note on failure since the minimum version is unverified.
- P3 rigs: Rig helpers live in `commands/rigs/_shared.jsx` under `MCP.rigs.*` (the underscore sorts first in the assembler). Panel idioms (raw `setValue`, the panels' own `easeKeys` with 0.1 influence on the outer handles) are kept over the shared easing library so the rigs match the panels exactly.
- P3 rigs: `list-rigs` reads descriptions registered by each rig file in ExtendScript, so the panel code is the single source of the parameter list.
- P3 rigs: The tools take explicit layer references instead of the panels' selection, require an existing composition instead of creating one, keep zero values instead of the panels' `parseFloat(x) || default` fallback, default `addBackground` to false, and reject a Power Warp incoming layer that equals the outgoing or depth layer (the panel silently dropped it). Power Warp keeps `comp.time = mid` and has no `openInViewer` argument because the panel never opened the viewer.
- P3 rigs: `#include` from the ScriptUI Panels folder was reasoned about but not tested; the panels stay self-contained and `panels/README.md` states the rule: change `commands/rigs/` first, then mirror into the panel.
- P3 layers: Camera focal-length presets use `zoom = compWidth * focalLength / 36` (35 mm film width); a camera created without a position sits at the comp centre at `z = -zoom` so the default framing is kept. Two-node point of interest is written to `ADBE Anchor Point`, which is how After Effects exposes it.
- P3 layers: Light "Casts Shadows" is written as 1 or 0 on the tri-state property; unverified.
- P3 layers: `split-layer-at-time` renames the halves with " 1" and " 2" suffixes (opt out with `keepNames`) so `{name}` references stay unambiguous; the upper copy keeps the later part, like Split Layer in After Effects.
- P3 layers: `set-layer-flags` skips a flag whose attribute reads back as undefined on that layer type instead of failing, because ExtendScript silently accepts assignments to unknown attributes.
- P3 layers: `set-layer-track-matte` uses `setTrackMatte` on After Effects 23 and later; on older versions it moves the matte directly above the layer and sets `trackMatteType`.
- P3 layers: Bounds maths for align, distribute, anchor point, fit and get-layer-bounds is 2D (anchor, position, scale, Z rotation); parenting and 3D are reported in notes. `distribute-layers` "centers" needs three layers, "spacing" needs two. `sequence-layers` defaults the interval to the previous layer's duration and clamps crossfade keys to each layer's duration.
- P3 layers: `select-layers` is read-only on the bridge (no project change) but keeps the default tool annotations since it changes UI state.
- P3 camera: A camera or light counts as two-node only when its auto-orient is "camera or point of interest"; the point of interest is read by display name with a fallback to matchName `ADBE Anchor Point`. One-node dolly and push-in assume a +Z view axis; one-node orbit becomes a Y Rotation key pair instead of a position circle. Orbit on two-node cameras writes linear keys every `sampleFrames` (default 2) with easing applied by shaping the sampling progress.
- P3 camera: Iris shapes accept 1 to 10 numerically but only nine names are mapped, matching the After Effects dropdown. Material tri-state fields accept booleans or "off", "on", "only".
- P3 time: `freeze-frame-at` reads the source time from Time Remap after enabling it and writes one hold key at the in point; the Freeze Frame menu command is not used. `set-speed` and `reverse-layer` keep the in point by measuring the shift after setting stretch and moving the start time back. `loop-layer` moves the last time-remap key one frame earlier before adding `loopOut`. `set-time-remap-keyframes` replaces After Effects' seed keys only when the call just enabled remapping.
- P3 audio: `audio-to-keyframes` runs the Convert Audio to Keyframes menu command with only the target selected and finds the new layer by id difference; `useLayerRange` temporarily sets the work area to the layer's range. `markers-from-beats` snaps to frames by default, labels downbeats red, names sub-beats "beat.sub", and caps at 5000 markers.
- P3 workflow: `snapshot-composition` caps at `maxLayers` (default 100), excludes shape contents unless asked, and carries `snapshotVersion: 1`. `apply-snapshot` matches by name (ties broken by index), replaces keys on properties that have snapshot keys, adds missing effects by matchName, and reports what it cannot restore (masks, shape contents, order and parenting, layer styles, timing, markers).
- P3 workflow: `find-layers` treats `/pattern/flags` as a regex and anything else as a case-insensitive substring. `replace-color` compares Euclidean RGB distance in 0 to 1 space, changes solids at the footage item level (every layer using the solid changes) and leaves gradient fills alone. `relink-fonts` with "missing" needs After Effects 23 and `app.fonts.missingOrSubstitutedFonts`.
- P3 text: Text animator reveal scheme: forward keys Start 0 to 100, backward keys End 100 to 0, center keys Start 50 to 0 and End 50 to 100 with the selector in subtract mode so the middle finishes first. `delay` is measured from the layer's in point. `typewriter` forces linear easing, a square shape and zero smoothness; `wave-y-position` adds a wiggly selector and writes no keys.
- P3 text: `set-text-box` sets `TextDocument.boxText`, reads it back and fails with `unsupported` when the flag did not take. `convert-text-to-shapes` runs the Create Shapes from Text menu command with only the target selected and finds the "<name> Outlines" layer.
- P3 shapes: A numeric group reference is the 1-based item index in Contents; modifiers, trim paths and repeaters default to the Contents root when no group is given. Trim Paths offset is in degrees (360 is one lap), matching the After Effects property. Gradient colour stops cannot be written by scripting; they are accepted and reported in warnings. `set-shape-path` refuses parametric rectangles, ellipses and stars instead of converting them silently.
- P3 masks: `mask-reveal-animation` directions name the way the wipe edge travels; the feather variant keys Mask Feather from 200 to 0 and the expansion variant from minus half the larger dimension to 0. Ellipse masks are four bezier vertices (kappa 0.5523) and rectangles four straight vertices so wipe keys interpolate vertex for vertex. `create-mask-from-shape-layer` ignores rotation, scale and rectangle roundness.
- P3: The final count is 189 tools (181 through the bridge, 8 Node-only) in 18 groups; `docs/PLAN.md` listed 189 with slightly different group boundaries (create-shape-layer and create-text-layer count under shapes and text, `list-tools` and `get-help` form a help group).
- P3: Every input field must carry a description; a unit test enforces it, and the 62 fields the workers left bare were described during integration.
- P4: `get-help` splits the guide on level-2 headings and matches a topic by slug, substring of the slug, or substring of the title, so "craft", "animation-craft" and "5. Animation craft" all work.
- P4: Style references are resolved on the Node side before validation for every tool, so a `@style.h1` text style expands into the same fields a caller could pass by hand; the panel never sees the style file.
- P4: Resources call the same bridge commands as the tools (`getProjectInfo`, `listCompositions`, `listLayers`, `listFonts`, `listAvailableEffects`, `listRigs`) and return the bridge error JSON instead of throwing when After Effects is not running.
- P5: The ExtendScript library is unit-tested in a Node vm with the After Effects globals stubbed (`KeyframeEase`, `KeyframeInterpolationType`, `app`), after deleting the ES5 array and object methods and `JSON` from the context so the polyfills and the JSON shim are exercised.
- P5: Tests use vitest; the mock After Effects bridge runs in-process from a temporary folder, and one test tool file per group calls tools through an in-memory MCP client so the full server path is covered.
- P5: Continuous integration also regenerates `docs/TOOLS.md` on Linux and fails when it differs from the committed file, and greps the tree for em dashes.
- P6: The panel guides were edited only to remove em dashes, change the title separator to a colon, and add a pointer to the matching rig tool; the panel `.jsx` files remain byte-identical to the originals.
- P6: `docs/media` holds placeholder stills and a placeholder GIF so the README renders; the README says how to replace them.
- P6: Development happened in a local clone at `/private/tmp/aftereffects-mcp`; the OneDrive working copy is fast-forwarded from GitHub after the final push.
